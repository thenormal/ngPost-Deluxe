# 进度与日志

## 进度条

底部的进度条显示当前阶段：

- **压缩**：正在创建压缩包。
- **par2**：正在生成恢复文件。
- **上传**：正在发送文章。这里还会显示速度、大小、文章数量和 **ETA**（预计剩余时间）。
- **已完成**、**已暂停**或**已停止**。

颜色表示状态：工作中为蓝色，暂停时为灰色，完成时为绿色，部分文章失败时为橙色，发布因错误而停止时为红色。百分比也会显示在窗口标题中。

ETA 是根据最近的速度得出的估计值：速度变化时它也会变化。

## 日志

日志会为各行着色：阶段、成功、警告和错误都很容易区分。一次发布结束时，日志会显示一份摘要，列出各阶段（压缩、par2、上传）的用时和总用时。

## 延迟

一次发布结束时，日志还会显示**延迟**：与服务器往返一次（POST 命令及其应答，不含数据）以及建立连接的中位用时。它只根据 ngPost 本来就在做的事情来测量，不会为此额外发送任何内容。数值较高（超过半秒）表示延迟来自网络、与服务器之间的距离或服务器本身，例如使用了 VPN，而不是您的电脑。

## 诊断报告

如果出现问题，请点击快速发布中日志下方的**诊断报告**按钮，它会保存一份程序所做操作的报告，其中包含每台服务器的**延迟**部分（连接、SSL、登录、往返：最小值、中位数、第 95 百分位和最大值）以及**通知**部分（通知哪些内容、系统通知是否已开启且可用、设置了哪些渠道，以及最近一次失败；地址和令牌绝不会写入）。这是一个文本文件，求助时可以作为附件。分享前请先检查：其中不应包含您的密码。

## 通知

ngPost 可以在您的发布完成时通知您，这样您就不必一直盯着窗口。它在**设置**的类别**通知**中设置，分为两部分：**通知什么**（发布完成、发布出现错误或失败、全部结束后发送一条消息还是每次发布发送一条）和**把消息发送到哪里**。在带窗口的程序中，系统通知默认就是开启的；其他渠道需要填写地址。

- **系统通知**：从通知区域的图标发出的消息（仅桌面版；默认开启，可以关闭）。在 Windows 中，它与其他通知一样显示，并保留在通知中心；如果您没有看到，请检查 Windows 的通知和专注助手（“勿扰”）是否把它隐藏了。
- **Discord**：粘贴 Discord webhook 的地址。
- **Telegram**：您的机器人令牌（token）以及接收消息的聊天 ID。
- **其他 webhook**：任何接受带有 `title` 和 `text` 的 JSON POST 请求的地址（类似 Slack 的工具、ntfy、Home Assistant）。

选择通知哪些内容（完成、错误或失败）以及方式：**所有发布完成后发送一条消息**（默认，最适合自动发布）或**每次发布后发送一条消息**。点击**发送测试消息**可以立即看到是否正常工作。

消息包含发布的名称、结果、大小、用时和速度，但绝不包含密码或文件名。地址和令牌与其他密码一样，以明文保存在配置文件中：请妥善保密。如果某条消息无法发送，日志中会有一行提示，而发布本身不受影响。

在命令行或 Docker 中，请使用选项 `--notify_discord`、`--notify_telegram_token`、`--notify_telegram_chat`、`--notify_webhook` 和 `--notify_when each|all_done`，或使用配置文件中的 `notify_*` 键。
